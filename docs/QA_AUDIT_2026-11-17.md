# EstateFlow QA audit — 17 November 2026

## Release result

The audited branch passes the production build, static analysis, formatting, TypeScript checks, focused MySQL regressions, and the complete desktop/mobile browser matrix. The browser command now creates a clean `estateflow_test` database and fixtures before every run so results do not depend on earlier manual or automated activity.

## Coverage completed

- Roles: main admin, office admin, accountant, sales agent, and booking agent.
- Workspaces: dashboard, inventory and setup, bookings and calculator, customers, follow-ups, receipts, expenses, salaries, payment accounts, owner and operational reports, imports, business settings, team access, profile, and appearance.
- Journeys: login/logout, keyboard login, access denial, customer creation and identity, private document upload/download, follow-up completion, plot catalogue maintenance, simplified booking, automatic sole purchaser, fixed down-payment discount, installment schedule, payment preparation, final booking, file submission controls, receipt posting, opening balances, expenses, and bank reconciliation.
- UI: desktop Chrome, iPhone 13 viewport, dialogs and menus, form labels, responsive filters, horizontal overflow, light/dark theme, and English/Urdu `lang`/`dir` switching.
- Technical: MySQL 8.4 migrations, exact decimal finance calculations, authorization, stale-version handling, idempotent replay, PHPStan, Pint, TypeScript, frontend lint/format, and optimized asset build.

## Confirmed defects and resolutions

| Finding | Severity | Resolution |
| --- | --- | --- |
| A sales agent could receive a 403 while saving the first terms record with an unnormalized zero discount. | High | Initial zero is now treated as no discount change; a positive initial discount and every later discount change still require an authorized admin. |
| Browser fixtures and booking assertions still followed the older multi-step purchaser workflow. | Medium | Coverage now follows the approved simplified redirect to terms, verifies the automatic 100% sole purchaser, then checks confirmation and the payable down payment. |
| The settings browser test expected the intentionally hidden late-charge section. | Low | It now verifies the reduced settings navigation and the supported payment-method section. |
| Repeated E2E runs reused database rows and rate-limit cache, causing duplicates, already-booked fixtures, and false 429 failures. | High (test reliability) | Global setup now clears cache, recreates the isolated database, and reseeds deterministic role/booking fixtures. Reconciliation also starts with clean E2E rate counters. |
| Existing coverage did not systematically open every main page for each office role or validate Urdu direction and theme behavior. | Medium | A navigation audit now checks all admin pages, shared role pages, inventory dialog/menu triggers, both themes, Urdu RTL, return to English, client errors, HTTP status, and horizontal overflow. |
| The exact-quote backend test used an incomplete purchaser even though simplified booking correctly requires CNIC and address. | Low (test correctness) | The fixture now supplies the required identity and expects the current direct-to-terms redirect. |

## Environment notes

- Local JavaScript builds must put `.runtime/php84` before the system XAMPP PHP 8.1 in `PATH`, because Wayfinder invokes `php` during Vite startup and Laravel 13 requires PHP 8.4.1 or newer.
- On this Windows host, Playwright completes correctly but Laravel's `artisan serve` child may remain alive after the report is printed. The audit stopped that test-only process explicitly; it does not affect production PHP-FPM/hosting behavior.
- Browser fixtures use synthetic `demo.*@estateflow.test` accounts and the isolated `estateflow_test` schema only.

## Release gate

No confirmed application defect remains open from this audit. Production deployment should use the normal CI/CD path after review of this branch; do not copy E2E data or its synthetic credentials to production.
